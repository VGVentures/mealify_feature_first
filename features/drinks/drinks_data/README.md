# drinks_data

The data layer for drinks. Implements `IDrinksRepository` from
[`drinks_domain`](../drinks_domain).

Two data sources behind one repository: TheCocktailDB over HTTP, and a local Drift
database as a cache. Which one answers a given call is this package's business and
nobody else's.

## What lives here

| Path | Contents |
| --- | --- |
| `src/data_sources/cocktaildb_api_client/` | `CocktailDbApiClient`, `CocktailDbApiHttpException` |
| `src/data_sources/cocktaildb_api_client/dtos/` | `ApiDrink`, `SingleDrinkResponse` |
| `src/data_sources/drinks_database/` | `DrinksDatabase`, `drinks.drift`, generated Drift code |
| `src/mappers/` | `ApiToDomainDrinkConverter`, `DbToDomainDrinkConverter` |
| `src/repositories/drinks_repository.dart` | `DrinksRepository` |

## How a read works

`DrinksRepository` takes both data sources and both converters through its
constructor, so a test can supply fakes for any of them. A read checks the local
database first, falls back to the API, writes what it fetched back to the database,
and returns a domain `Drink` either way.

## DTOs never escape

`ApiDrink` is shaped like TheCocktailDB's JSON. `DbDrink` is generated by Drift.
Neither leaves this package, so nothing downstream is coupled to Drift or to the
API's response shape.

Converters extend `Converter<Input, Output>` from `dart:convert`, live in
`src/mappers/`, and are not exported. They are an implementation detail of the
repository.

## Public API

The barrel exports the repository and the data sources. The app needs both to
construct the repository. `ApiDrink` is not exported either: it is
TheCocktailDB's wire shape, and a consumer that could name it could bind to the
api instead of to `Drink`.

## Who depends on this

Only [`mealify_app`](../../../apps/mealify_app), which constructs
`DrinksRepository` and provides it as an `IDrinksRepository`.
[`drinks_presentation`](../drinks_presentation) never imports this package.

## Testing

`dart run melos test` from the repo root, or `fvm dart test` here. This is a pure
Dart package, so its tests use `package:test`.

The API client tests include integration tests that hit TheCocktailDB over the
network, so they can fail when it is unreachable.
